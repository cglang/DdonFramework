## 七、关键接口约定

### 前后端通信协议

```typescript
// Request（前端 → 后端）
interface BridgeRequest {
  id: string      // 请求 ID，用于关联响应
  method: string  // 方法名，如 "ReadAllPlc"
  payload?: string // JSON 字符串参数
}

// Response（后端 → 前端）
interface BridgeResponse {
  id: string      // 对应请求 ID
  success: boolean
  data?: string   // JSON 字符串结果
  error?: string  // 错误信息
}

// Event（后端 → 前端）
interface BridgeEvent {
  name: string    // 事件名，如 "PlcDataUpdatedEvent"
  data?: string   // JSON 字符串载荷
}
```

### 传输方式

| 模式 | 方向 | 方式 | 协议 |
|------|------|------|------|
| 桌面 | 前端→后端 | `chrome.webview.postMessage` | JSON over WebView Message |
| 桌面 | 后端→前端 | `CoreWebView2.PostWebMessageAsString` | JSON over WebView Message |
| 浏览器 | 前端→后端 | `fetch /api/bridge/invoke` | HTTP POST JSON |
| 浏览器 | 后端→前端 | `fetch /api/bridge/event` | HTTP POST JSON（或 SignalR） |

### 特性标记约定

| 特性 | 用途 |
|------|------|
| `[BridgeService]` | 标记类为可被前端调用的服务 |
| `[BridgeMethod(Name)]` | 标记方法为可被前端调用的入口，Name 为前端 invoke 的方法名 |
| `[BridgeEvent(Name)]` | 标记事件模型（当前为文档标记，分发时按类名匹配） |

## 九、各模块职责边界

| 模块 | 职责 | 不负责 |
|------|------|--------|
| **Protocol** | 通信协议 DTO（Request/Response/Event） | 任何业务逻辑 |
| **Annotations** | 标记特性（[BridgeService] 等） | 反射扫描 |
| **Platform** | 平台能力抽象接口（IClipboard 等） | 具体实现 |
| **Transport** | 传输层抽象 + 实现（HTTP / WebView） | 消息解析、业务调度 |
| **Bridge** | 通信入口 + 请求分发 + 反射调度 | 传输细节 |
| **AspNet** | ASP.NET Core 集成、Controller、DI 注册 | 应用启动 |
| **Hosting** | 应用启动、Kestrel 生命周期 | 平台适配 |
| **Wpf / Maui** | 桌面宿主、窗口、WebView、平台实现 | 业务逻辑 |
| **Client（TS）** | 前端 SDK，环境自动识别 | UI 框架 |
