**基于 ASP.NET Core 的跨平台桌面应用框架**

## 一、设计目标

* ASP.NET Core 作为整个应用运行时
* Web(Vue/React)作为唯一 UI
* WPF/MAUI 只是宿主
* Web 页面既可以独立浏览器运行，也可以作为桌面应用运行
* 业务代码无需关心运行环境
* 前后端通信统一抽象

```ts

    address:"DB1.DBX0.0"
});
```

```text

↓

↓

Controller
```

桌面：

```text

↓

WebView Message

↓

```

## 2.Event

后台：

```text

↓

↓

```

桌面：

```text

↓

↓

```

```ts

```

# 七、设计原则

整个框架建议坚持以下原则：

1. **ASP.NET Core 是唯一业务运行时**，所有业务逻辑、后台任务、插件、DI 都运行在这里。
2. **Web 是唯一 UI**，不为 WPF 或 MAUI 单独开发界面。
3. **宿主只是平台适配层**，负责窗口、WebView 和原生能力，不承载业务逻辑。
4. **UiBridge 是唯一通信入口**，业务代码永远只调用 `invoke`、`publish`、`on` 等统一接口。
5. **Transport 负责环境差异**，浏览器走 HTTP/SignalR，桌面走 WebView 消息，业务层完全无感知。
6. **Platform 负责平台能力抽象**，文件对话框、托盘、剪贴板等通过接口统一访问。
7. **前端可以独立运行**，既能作为普通 Web 应用开发和调试，也能无缝嵌入桌面应用。

## 八、这个框架的定位

从定位来看，它不是 Electron 的替代品，也不是 MAUI 或 Blazor 的封装，而是一个**以 ASP.NET Core 为核心运行时**的桌面应用框架。

它借鉴了 Electron、Tauri 的理念，但保持 ASP.NET Core 完整的生态优势：DI、HostedService、中间件、日志、配置、插件等全部可以直接复用；前端保持标准 Web 开发方式；宿主可以在 WPF、MAUI 之间切换，未来甚至可以扩展到 Electron、Tauri，而业务代码几乎无需改动。这样的分层也为后续增加热更新、插件市场、权限管理、状态同步等能力预留了良好的扩展点。
