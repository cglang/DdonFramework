## 二、启动流程

```
Sample.App.OnStartup()
  │
  ├─ 1. 读取 appsettings.json
  │      ├─ Backend.Urls            ← Kestrel 监听地址
  │      └─ ViteDevServer.Enabled   ← 是否启动 Vite 开发服务器
  │
  ├─ 2. new Wpf.MainWindow()
  │      └─ ApplyConfig(title, loadingTitle, loadingText)
  │           └─ Show()  → 显示加载动画
  │
  ├─ 3. new DesktopHost().StartAsync()
  │      ├─ WebApplication.CreateBuilder
  │      ├─ builder.UseUrls(Backend.Urls)
  │      ├─ builder.Logging.ClearProviders()
  │      ├─ services.AddDesktop()            ← IBridgeDispatcher, IUiBridge
  │      ├─ services.AddDesktopTransport<WebViewTransport>()
  │      ├─ services.AddSingleton<AuthService>()
  │      ├─ services.AddSingleton<PlcReadService>()
  │      ├─ AddControllers + AddApplicationPart
  │      ├─ app.UseCors / UseFileServer / MapControllers
  │      ├─ app.StartAsync()                 ← Kestrel 就绪
  │      └─ OnInitialized 回调:
  │           ├─ _mainWindow.SetLoadingText("正在准备浏览器引擎...")
  │           ├─ _mainWindow.BridgeDispatcher = IBridgeDispatcher
  │           └─ _mainWindow.InitializeWebViewAsync(url)
  │                ├─ WebView2 初始化
  │                ├─ 注册 WebMessageReceived
  │                └─ 隐藏加载动画 → 显示 WebView → Navigate(url)
  │
  └─ 前端 Vue 应用
       ├─ 路由拦截 → 无 token → 跳 /login
       └─ 用户登录后 → 跳 /dashboard
```

### 调试模式 (ViteDevServer.Enabled = true)

```
Kestrel（5000）← 代理 /api ← Vite Dev Server（5173）
                               ← 热更新 + TS 编译
                               ← WebView 导航到此
```

### 生产模式 (ViteDevServer.Enabled = false)

```
npm run build → wwwroot/    ← Kestrel（5000）UseFileServer 直接 serve
                               ← WebView 导航到此
```

## 三、前后端通信

### 3.1 invoke：前端调用后端

```
前端调用 → DispatchAsync(method, payload) → 反射调用 [BridgeMethod]
                                                     ↓
                                             返回 object?
```

**桌面模式**（WebView Message）：
```
JS:  window.ui.invoke('Plc.ReadAllPlc')
  →  chrome.webview.postMessage({ type, data })
  →  C#: WebMessageReceived → WebViewTransport.HandleMessage
  →  BridgeDispatcher.DispatchAsync
  →  PlcReadService.ReadAllPlc()
  →  result → PostWebMessageAsString → JS Promise resolve
```

**浏览器模式**（HTTP）：
```
JS:  window.ui.invoke('Auth.Login', {...})
  →  fetch POST /api/bridge/invoke
  →  BridgeController.Invoke
  →  BridgeDispatcher.DispatchAsync
  →  AuthService.Login()
  →  HTTP 200 → BridgeResponse → JS Promise resolve
```

**协议模型**（`object?` 传输，仅一次序列化）：
```json
// 请求
{ "id": "uuid", "method": "Plc.ReadAllPlc", "payload": null }

// 响应
{ "id": "uuid", "success": true, "data": { ... } }

// 带参数请求
{ "id": "uuid", "method": "Plc.WritePlc", "payload": { "address": "DB1.DBX0.0", "value": true } }
```

Payload 和 Data 均为 `object?` 类型，`System.Text.Json` 按运行时类型自动序列化，仅一次序列化 + 一次传输封包。

### 3.2 publish/on：后端推送事件到前端

```
C#:  await bridge.PublishAsync(new EventData())
  →  PostWebMessageAsString({ type: "event", data: {...} })
  →  JS: on('EventName', handler) 触发
```

### 3.3 环境自动识别

```ts
// bridge.ts
const isWebView = !!window.chrome?.webview
const transport = isWebView ? new WebViewTransport() : new BrowserTransport(baseUrl)
```

## 四、如何创建新的业务服务

### 后端

```csharp
using Ddon.Desktop.Annotations;
using Ddon.Desktop.Bridge;

[BridgeService(Name = "MyService")]
public class MyService
{
    private readonly IUiBridge _bridge;

    public MyService(IUiBridge bridge)
    {
        _bridge = bridge;
    }

    [BridgeMethod(Name = "DoSomething")]
    public Task<string> DoSomething(string input)
    {
        // 业务逻辑
        return Task.FromResult($"Hello {input}");
    }

    [BridgeMethod(Name = "StartBackgroundTask")]
    public async Task StartBackgroundTask()
    {
        // 启动后台逻辑，完成后通知前端
        await Task.Delay(1000);
        await _bridge.PublishAsync(new TaskCompletedEvent());
    }
}
```

### 注册到 DI

```csharp
// App.xaml.cs → builder.ConfigureServices
services.AddSingleton<MyService>();
```

### 前端调用

```ts
const result = await window.ui.invoke<string>('MyService.DoSomething', { input: 'world' })
```

## 六、后端控制前端路由跳转

### 推荐方式：发布导航事件

```csharp
// C# 端
[BridgeEvent(Name = "Navigate")]
public class NavigateEvent
{
    public string Route { get; set; } = "";
}

await bridge.PublishAsync(new NavigateEvent { Route = "/dashboard" });
```

```ts
// Vue 端（App.vue 或 router/index.ts）
window.ui.on('NavigateEvent', (event: { route: string }) => {
  router.push(event.route)
})
```

## 七、登录流程

```
Vue Router 拦截 → (/login)
  │
  ├─ LoginView.vue: window.ui.invoke('Auth.Login', { username, password })
  │     └─ AuthService.Login() → 验证 → 返回 token
  │
  ├─ sessionStorage.setItem('token', token)
  ├─ window.ui.invoke('Auth.StartPlcSimulator')
  │     └─ AuthService.StartPlcSimulator() → PlcEngine.Start() → 定时推数据
  │
  └─ router.push('/dashboard')
```

路由守卫：

```ts
// router/index.ts
router.beforeEach(async (to) => {
  if (to.name === 'Login') return true
  const token = sessionStorage.getItem('token')
  if (!token) return { name: 'Login' }
  return true
})
```

## 十、项目设计原则

1. **ASP.NET Core 是唯一业务运行时** — 所有业务逻辑、DI 都运行在 Kestrel 中
2. **Web 是唯一 UI** — WPF 只是平台宿主，不承载业务界面
3. **宿主可替换** — WPF / MAUI 切换时业务代码无需改动
4. **Bridge 是唯一通信入口** — 前端永远只调 `invoke`、`on`、`publish`
5. **Transport 负责环境差异** — 浏览器走 HTTP，桌面走 WebView Message，业务层无感知
6. **Platform 负责平台能力** — 文件对话框、剪贴板等通过接口统一访问
7. **前端可独立运行** — 既能作为普通 Web 应用开发调试，也能嵌入桌面宿主
8. **[BridgeService(Name)] 命名空间** — 前端调用使用 `ServiceName.MethodName` 格式，避免方法名冲突
